# SHYOSKI ARCHITECTURE MASTER DOCUMENT V2.0

## 1. PRODUCT VISION

Shyoski is a multi-tenant internship, training, certification, and placement management SaaS platform.

The platform enables organizations, certification providers, training institutes, colleges, startups, and companies to run structured internship and training programs under their own organization while using a shared Shyoski infrastructure.

Shyoski must support:

* Multiple organizations
* Multiple internship domains
* Multiple batches
* Multiple administrators
* Student progress tracking
* Assignment evaluation
* Team collaboration
* Payments
* Certificate generation
* Certificate verification
* Job and placement opportunities
* White-label branding (future)
* Enterprise scale (100,000+ students)

# 3. TENANT MODEL

Every organization is a tenant.

Examples:

Organization A

* Certification Provider

Organization B

* College

Organization C

* Startup

All organizations share the same Shyoski infrastructure.

Every business entity must belong to exactly one organization.

Required field:

organizationId

This field must exist on:

* users
* batches
* submissions
* groups
* certificates
* payments
* jobs
* notifications
* analytics
* audit logs

No document should exist without organization ownership.

# 4. USER ROLES

SUPER_ADMIN

Capabilities:

* Manage entire platform
* Manage organizations
* View all students
* View all payments
* View all certificates
* View all analytics

---

ORG_ADMIN

Capabilities:

* Manage own organization
* Create batches
* Manage students
* Manage evaluators
* Manage jobs
* View organization reports

Restrictions:

* Cannot access other organizations

---

MENTOR

Capabilities:

* View assigned batches
* Guide students
* Access group information

Restrictions:

* Cannot modify platform settings

---

EVALUATOR

Capabilities:

* Review submissions
* Approve or reject assignments
* Provide feedback

Restrictions:

* Limited to assigned batches

---

STUDENT

Capabilities:

* Join batches
* Submit assignments
* Create or join groups
* Access certificates
* Apply to jobs

Restrictions:

* Access only own data

---

EMPLOYER

Capabilities:

* Verify certificates

Restrictions:

* Read-only verification access

---

GUEST

Capabilities:

* View public pages
* View internship listings

Restrictions:

* No protected access

# 15. SECURITY REQUIREMENTS

* Authentication
* Role
* organizationId

Every query must include organizationId filtering.

Super Admin is the only exception.

4. Never break backward compatibility.
5. Always create migration scripts.
6. Always preserve existing production data.
7. Every new collection must support multi-tenancy.
