# SHYOSKI V2.1 CORE BUSINESS DECISIONS

## FINAL DECISIONS

### Platform Model

Shared Platform

Single Domain:

https://shyoski.in

All organizations operate inside the same platform.

No white-label subdomains in V2.

---

### Revenue Model

Shyoski receives all payments.

Organizations do not directly receive payments.

Future revenue sharing may be added but is not part of V2.

---

### Certificate Model

Certificates are co-branded.

Certificate contains:

* Shyoski Logo
* Organization Logo
* Student Name
* Batch Name
* Completion Date
* Verification QR
* Certificate Number

Certificate generation must be dynamic.

Organization logo is fetched from organization configuration.

---

### Student Membership Model

A student may belong to multiple organizations.

Examples:

Student A

* Organization Alpha
* Organization Beta

Student B

* Organization Alpha

Student C

* Organization Gamma

Therefore users collection must NOT contain a single organizationId.

## ACCESS CONTROL RULES

SUPER_ADMIN

Can access:

* All organizations
* All students
* All batches
* All payments

---

ORG_ADMIN

Can access:

Only organizations where:

organization_memberships.membershipRole == org_admin

---

STUDENT

Can access:

Only batches where student has membership.

---

MENTOR

Can access:

Assigned batches only.

---

EVALUATOR

Can access:

Assigned review queues only.

---

## CERTIFICATE FLOW

Student
→ Completes Batch
→ Final Submission Approved
→ Payment Successful
→ Certificate Generated

Certificate Header:

[Organization Logo] + [Shyoski Logo]

Certificate Number:

SHY-ORGCODE-YEAR-RANDOM

Example:

SHY-ABC-2026-7F9K3A

Verification:

https://shyoski.in/verify/SHY-ABC-2026-7F9K3A

---

organizationId
organizationSlug

Create Org Admin

Create Batches

Invite Students

---

## NON-NEGOTIABLE ARCHITECTURE RULES

1. Users are global.
2. Organizations are isolated.
3. Membership controls access.
4. Batch belongs to one organization.
5. Student can belong to many organizations.
6. Certificates are co-branded.
7. Shyoski receives all payments.
8. Shared platform architecture.
9. No white-label support in V2.
10. Every protected API must validate organization membership.
