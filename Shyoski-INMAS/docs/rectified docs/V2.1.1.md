# SHYOSKI ARCHITECTURE CLARIFICATIONS V2.1.1

## A. Global vs Tenant User Roles

Decision:

users.globalRole only supports:

* super_admin
* user

Default:

user

Example:

{
uid: "...",
email: "...",
globalRole: "user"
}

Organization-specific permissions belong ONLY in:

organization_memberships.role

Example:

User:

{
uid: "123",
globalRole: "user"
}

Organization Memberships:

{
organizationId: "A",
uid: "123",
role: "student"
}

{
organizationId: "B",
uid: "123",
role: "org_admin"
}

Result:

Same user can be:

Student in Organization A

Org Admin in Organization B

without conflict.

Rule:

Never use users.globalRole for tenant permissions.

Only super_admin uses globalRole.

---

## B. Never Remove organizationId Rule

Clarification:

Original rule is incorrect.

Correct Rule:

Every tenant-owned business entity must contain organizationId.

Applies To:

batches

submissions

groups

group_chats

payments

certificates

jobs

notifications

audit_logs

Does NOT Apply To:

users

organizations

organization_invitations

Reason:

Users are global identities.

Organizations are root entities.

---

## C. Batch Mapping For Mentors And Evaluators

Decision:

Create dedicated collection:

batch_assignments

Schema:

{
_id,
organizationId,
batchId,
uid,
role,
assignedBy,
assignedAt
}

Role Values:

mentor

evaluator

Examples:

Mentor A
→ Full Stack Batch

Mentor A
→ Cybersecurity Batch

Evaluator B
→ Full Stack Batch

Rule:

Mentors and evaluators must be assigned explicitly.

Organization membership alone does not grant batch access.

## D. Employer And Guest Roles

Decision:

Neither role requires account creation.

Guest:

Anonymous Visitor

Capabilities:

Landing Page

Public Information

Certificate Verification

Public Jobs

No Database Record Needed.

---

Employer:

Anonymous By Default

Can:

Verify Certificates

View Public Verification Pages

No Login Required.

Future Enterprise Feature:

Employer Accounts

Not Included In V2.

Remove Employer And Guest from RBAC.

Treat as public actors.

---

## E. Payment Gateway Configuration

Decision:

Single Global Payment Gateway

Owned By Shyoski

Configuration:

One Razorpay Account

One Merchant Account

One API Key Set

Example:

Shyoski Razorpay Account

↓

Organization A Batch

Organization B Batch

Organization C Batch

All payments collected centrally.

---

Why Keep organizationId On Payments?

For:

Revenue Analytics

Organization Reports

Certificate Eligibility

Audit Logs

Example:

{
paymentId: "...",
organizationId: "ABC",
batchId: "123",
amount: 499
}

This allows:

Revenue By Organization

Revenue By Batch

Student Payment Tracking

without requiring separate merchant accounts.
