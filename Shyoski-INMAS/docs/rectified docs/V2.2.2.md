## 2. Cloudflare Worker Database Initialization

Decision:

YES.

Cloudflare-specific env injection must be used.

---

Approved Pattern

getDb(env)

NOT

getDb()

NOT

process.env

---

Reason

Cloudflare Workers do not expose traditional Node.js environment variables.

Bindings are supplied through:

c.env

---

Example Flow

Route

↓

c.env

↓

Service

↓

getDb(c.env)

↓

MongoDB

---

Database Helper

Must:

Use Lazy Initialization

Reuse Existing Client

Avoid Per-Request Connection Creation

---

Additional Rule

MongoClient must exist in module scope.

Example Conceptually

cachedClient

cachedDb

initialized once

reused afterwards

---

Decision:

Approved.

---

## 3. Resource Organization Resolution

Decision:

YES.

Sequential Authorization Flow Accepted.

---

Standard Flow

Authenticated User

↓

Fetch Resource

(submission/group/certificate)

↓

Extract organizationId

↓

Validate Membership

↓

Validate Role

↓

Execute Action

---

Example

GET /submissions/:id

↓

Load Submission

↓

submission.organizationId

↓

Query organization_memberships

↓

Verify Membership

↓

Verify Role

↓

Return Response

---

Reason

organizationId is authoritative on resource.

Avoids trusting frontend parameters.

Prevents tenant spoofing.

---

Performance Impact

Accepted.

Reason:

Single indexed lookup.

Membership lookup also indexed.

Expected latency minimal.

---

Future Optimization

Optional.

Context Resolver Middleware

Can cache resource lookup result:

c.set("submission", submission)

Subsequent middleware reuses loaded resource.

Avoid duplicate queries.

Not mandatory for MVP.
