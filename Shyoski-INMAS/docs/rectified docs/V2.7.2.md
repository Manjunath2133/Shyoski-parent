# SHYOSKI DATABASE CLARIFICATIONS V2.7.2

## 1. Batch Staffing Uniqueness

Decision:

A user CANNOT hold multiple staffing roles
inside the same batch.

Examples

Allowed

User A

Batch 1

Role = mentor

---

User A

Batch 2

Role = evaluator

---

User A

Organization X

Role = mentor

Organization Y

Role = evaluator

---

Not Allowed

User A

Batch 1

Role = mentor

AND

Batch 1

Role = evaluator

Rejected.

Reason:

Avoid permission ambiguity.

Avoid duplicate staffing records.

Simplify RBAC.

---

Required Unique Index

{
batchId: 1,
uid: 1
}

UNIQUE

---

Result

One staffing record per user per batch.

Role field remains:

mentor

OR

evaluator

Never both.

## 2. Verification Code Deprecation

Decision:

verificationCode removed.

---

Historical Reason

Originally intended for:

Randomized verification lookups.

---

Current Architecture

Certificate Number

Already:

Globally Unique

Human Readable

Public Safe

Immutable

QR Friendly

---

Verification Route

---

QR Contents

Store:

Full Verification URL

Example:

https://shyoski.in/verify/SHY-2026-ABC-A91K2X

---

Certificate Schema Simplification

Remove:

verificationCode

---

Certificate Schema

{
_id,

organizationId,

batchId,

uid,

certificateNumber,

certificateSnapshot,

status,

issuedAt
}

---

Indexes

uid

batchId

(uid + batchId)

---

Benefits

One identifier.

One lookup path.

One verification mechanism.

Reduced index overhead.

Simpler implementation.
